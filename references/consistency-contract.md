# 多页面与多模块一致性契约

在新增页面、拆分模块或复用页面模板时，用本次用户需求、项目现有代码和已确认规范确定基线。不同 HTML 文件代表不同页面，不代表手机和桌面两套版本；每个页面自身响应式适配。不要仅凭单个页面的偶然样式创建第二套风格。

## 先确定共享层

| 层级 | 应保持一致 | 允许因内容变化 |
| --- | --- | --- |
| 产品层 | 品牌色语义、字体族与字阶、间距尺度、圆角、阴影、图标语言、反馈语气 | 主题或活动样式，但须有明确适用范围 |
| 页面壳层 | 导航、页眉/页脚、内容最大宽度、栅格与边距、主要操作样式 | 不同页面类型的栏位和密度 |
| 组件层 | 同义按钮/输入/卡片/标签的状态、尺寸、可访问行为 | 明确命名的变体与内容长度 |
| 模块层 | 标题层级、模块间距、对齐、分割与状态表达 | 图文比例、内部排布和内容数量 |

优先引用已有 CSS 变量、共享 CSS 或组件。纯 HTML 多页项目可用共享样式表和一致的语义类；不要为了复用引入用户未要求的框架。同一 HTML 多模块项目可用组件类或局部变体，但不应让每个模块各自定义一套基础色值、字体和按钮。若项目已有局部风格差异，先判断它属于已批准的页面角色还是历史漂移。

## 逻辑复用

检查多个页面或模块是否重复实现相同职责的导航状态、表单校验、筛选、格式化、数据读取或事件处理。先找项目已有的共享函数/模块；确定行为和状态含义一致后，再把重复实现收敛到一个入口，由各页面调用。不要只因代码形状相似就合并不同业务流程，也不要为了少量一次性代码增加抽象。把稳定入口写进 `DESIGN.md` 的“组件与交互”，无需复制实现细节。

## 页面与模块清单

实施前列出受影响页面/模块及其关系：哪些共享壳层，哪些共享组件，哪些是有理由的例外。给新页面选已有的页面类型；没有可用类型时定义新类型的用途与边界。给新模块选已有的组件或模式；确需新变体时说明旧变体为什么不能表达该内容。

## 完成时核对

- 手机与桌面都能找到相同的核心内容和操作；隐藏、折叠或重排不会造成任务中断。
- 相邻页面的导航、页眉、内容边距、按钮、表单和反馈保持一致；不同页面类型的差异有原因。
- 同页模块的标题级别、正文行长、模块间距、卡片密度与分隔方式形成稳定节奏。
- 正常、悬停（适用时）、焦点、禁用、加载、空态和错误态使用同一语义；交互不只依赖 hover。
- 至少比较一个旧页面与一个新页面，或单页内两个相邻模块，在手机和桌面尺寸下检查。修复发现的漂移或明确记录例外。

检查结果只需列出实际发现和处理；不要为每个页面生成重复的长表格。
